# station 0.4.0 (not released yet)

0.4.0 moves station onto voxgig/struct's `$NOF` checker, which replaced
`$ONE` (D-2026-11-17-1). It needs struct 0.4.0, and an SDK generated by
an sdkgen that vendors that struct.


## What a 0.3.0 user will see change

- **An SDK generated before this release does not work beside it in
  ruby, perl or php, nor inside it in c, cpp or perl.** Those ports
  validate `station.json` with the struct the SDK carries, and an SDK's
  struct from before the change has no `$NOF`. `open()` then refuses a
  valid file, with errors such as `Expected field …base to be list, but
  found string`. Regenerate the SDK on an sdkgen that vendors struct
  0.4.0. typescript, javascript and go hold a struct of their own, so
  only the option-spec reading below reaches them.
- **A refusal reads `to be at least 1 of …`** where it read `to be one
  of …`, and a list where a map belongs reads `to be map`. The error
  codes are unchanged.
- **An option spec's `$NOF` admits each alternative's kind** when its
  count requires at least one alternative to admit the value, and any
  kind when it does not. A spec written with `$ONE` is read as one
  kind, a list, so an SDK generated before the change has its options
  checked wrongly.
