# station 0.4.0

Released from `main` in one run of `release.yml`:

- `@voxgig/station` on npm;
- `@voxgig/station-js` on npm;
- the Go module, at `go/v0.4.0`.

Every other port also declares 0.4.0, and is consumed from this
repository.

0.4.0 moves station onto voxgig/struct's `$NOF` checker, which replaced
`$ONE` (D-2026-11-17-1), in every port at once (W4.10). typescript
takes `@voxgig/struct` 0.4.0, javascript `@voxgig/struct-js` 0.2.0, and
go struct's `go/v0.2.0`. An SDK that runs beside station in ruby, perl
or php, or carries it in c, cpp or perl, needs sdkgen 4.48.0 or later,
the first release that vendors a struct with `$NOF`. create-sdkgen
0.31.12 scaffolds sdkgen 4.48.1.

0.4.0 also carries typescript's extension host (W8.6) and its first two
extension points (W9.1).


## What a 0.3.0 user will see change

- **An SDK generated before sdkgen 4.48.0 does not work beside this
  release in ruby, perl or php, nor inside it in c, cpp or perl.**
  Those ports validate `station.json` with the struct the SDK carries,
  and an SDK's struct from before the change has no `$NOF`. `open()`
  then refuses a valid file, with errors such as `Expected field
  …base.1 to be string, but found no value.` or `Expected field …base
  to be list, but found string`, depending on the sdkgen that generated
  the SDK. Regenerate the SDK on sdkgen 4.48.0 or later. typescript,
  javascript and go hold a struct of their own, so only the option-spec
  reading below reaches them.
- **A refusal reads `to be at least 1 of …`** where it read `to be one
  of …`, and a list where a map belongs reads `to be map`. The error
  codes are unchanged.
- **An option spec's `$NOF` admits each alternative's kind** when its
  count requires at least one alternative to admit the value, and any
  kind when it does not. A spec written with `$ONE` is read as one
  kind, a list, so an SDK generated before the change has its options
  checked wrongly.


## New in typescript

- **A Station hosts extensions** (W8.6, D-2026-11-14-1).
  `station.use(definition, options)` starts a voxgig/plugin definition
  in a host whose first instance is the Station, exported as
  `station/station`. `extensions()` lists them, `extension('<name>/<key>')`
  reads an export, and `close()` takes the host down first. `use()` on
  a closed Station raises `station_no_plugin`, as `connect()` does.
  typescript takes `@voxgig/plugin` `^0.2.0` for it.
- **Two extension points** (W9.1). `sdk.feature` is a chain over the
  caller's feature collection, run on every path that builds an SDK,
  and `sdk.bound` is a hook that hears of each client bound. A failing
  binding is a warning event, never a failed construction.

The design is [`station-extensions.md`](../design/station-extensions.md).
