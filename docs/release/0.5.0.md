# station 0.5.0

Released from `main` in one run of `release.yml`:

- `@voxgig/station` on npm;
- `@voxgig/station-js` on npm;
- the Go module, at `go/v0.5.0`.

Every other port also declares 0.5.0, and is consumed from this
repository.

0.5.0 carries what W10 asked of the typescript Station for its two
extensions, station-view and station-mcp, in the application's process
(D-2026-11-27-1). Only typescript's source changes. javascript, go and
the other ports carry the version alone.


## What a 0.4.0 user will see change

- **An op event's `corr` is the SDK's own id for the operation,** where
  its context has one (W10.7). sdkgen 4.50.0 and later put that id on
  the `telemetry` span, the `debug` entry and the `audit` record as
  `correlationId`, so a call's `op`, `http` and `error` events join its
  feature records. An SDK whose context has no id gets the adapter's
  own count, `c1`, `c2` and on, as before.


## New in typescript

- **`secrets()`** (W10.4) says which store answers each bound plugin's
  secret, and never reads a value. Each row gives the store chain and
  the resolution. Where no store has the secret, its remediation names
  the variable each env store would read, and says to add the secret to
  a configured store. A store that cannot answer ends the walk, as it
  ends a lookup, so a weaker store is never reported in its place.
- **`policies()`** (W10.4) gives each bound plugin's gates as solo mode
  applies them: its mode, hosts, allow, budget, resolve and capture,
  and `agentWrite`, its block's `agent.write`.
- **`PolicyStatus` and `SecretStatus`** are exported, the row types of
  the two.

station-mcp's `station_secrets` and `station_policy` tools read these
two (`station.md` §7). Against 0.4.0 they answer that the Station does
not report them.
